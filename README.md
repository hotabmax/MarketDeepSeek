# 🥕 ФрешМаркет — интернет-магазин продуктов на Django

Демонстрационный, но полностью рабочий продуктовый магазин: витрина с категориями,
поиском, сортировкой и пагинацией, корзина на сессиях, оформление заказа с проверкой
остатков и списанием товаров, а также админ-панель для управления каталогом и заказами.

## Возможности

**Витрина**
- Главная страница с баннером, разделами магазина и «хитами недели».
- Каталог: фильтр по категориям, поиск по названию и описанию, сортировка
  (популярность, цена, новинки, название), пагинация по 12 товаров.
- Карточка товара: описание, скидка со старой ценой, остаток, похожие товары.
- Адаптивная вёрстка без внешних CDN и CSS-фреймворков, доступная навигация.

**Покупки**
- Корзина в сессии: добавление, изменение количества, удаление,
  автоматическое удаление товаров, которых больше нет в продаже.
- Подсчёт суммы, доставки и остатка до бесплатной доставки.
- Оформление заказа: контакты, курьер/самовывоз, время доставки, оплата, комментарий,
  согласие на обработку данных; валидация телефона, адреса и остатков.
- Заказ сохраняется со снимком названий и цен, остатки списываются атомарно
  (`select_for_update`), корзина очищается, показывается страница подтверждения.
- Отслеживание заказа по номеру и телефону: таймлайн этапов, текущий статус,
  состав и история изменений. Доступ к деталям — только после проверки пары
  «номер + телефон», ссылки без проверки не раскрывают данные.
- Уведомления о действиях через `django.contrib.messages`.

**Администрирование** (`/admin/`)
- Категории с иконками, цветом подложки и порядком вывода.
- Товары с ценами, скидками, остатками, публикацией и эмодзи-иллюстрациями.
- Заказы: статусы, фильтры, поиск, позиции заказа, история статусов и групповые
  действия («Подтвердить», «В доставку», «Выполнен», «Отменить»). Каждое действие
  оставляет запись в истории заказа, которую видит покупатель.

**Качество**
- 80 автотестов: модели, каталог, корзина, форма оформления, весь путь заказа,
  обработка нехватки товара, отслеживание и история статусов.

## Стек

- Python 3.12, Django 6.1
- SQLite (легко заменить на PostgreSQL)
- Django Templates, чистый CSS и JavaScript (без сборки и npm)
- Django Admin для управления магазином

## Быстрый старт

Windows (PowerShell):

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python manage.py migrate
python manage.py seed_demo
python manage.py createsuperuser
python manage.py runserver
```

Linux / macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py seed_demo
python manage.py createsuperuser
python manage.py runserver
```

Откройте:

- витрина — <http://127.0.0.1:8000/>
- отслеживание заказа — <http://127.0.0.1:8000/orders/track/>
- админка — <http://127.0.0.1:8000/admin/>

> В этом рабочем каталоге миграции уже применены, демо-данные загружены,
> а суперпользователь создан: логин `admin`, пароль `admin12345`.
> **Смените пароль или удалите этого пользователя**, если разворачиваете проект
> где-либо, кроме локальной машины.

### Демо-данные

`python manage.py seed_demo` создаёт 8 категорий и 52 товара (с ценами, остатками,
скидками и описаниями). Команду можно запускать повторно — записи обновляются по `slug`,
дубли не появляются.

## Тесты

```bash
python manage.py test
```

Ожидаемый результат: `Ran 80 tests ... OK`.

Тесты разделены по приложениям:

- `catalog/tests.py` — модели, менеджер доступных товаров, скидки, слаги,
  фильтры, поиск, сортировка, пагинация, страницы каталога и товара;
- `cart/tests.py` — класс `Cart`, ограничения по остаткам, суммы и доставка,
  очистка недоступных товаров, HTTP-эндпоинты корзины;
- `orders/tests.py` — валидация формы, нормализация телефона, создание заказа,
  списание остатков, бесплатная доставка и самовывоз, нехватка товара,
  отслеживание по номеру и телефону, история статусов и действия админки.

### Поток оформления заказа

1. Пользователь добавляет товары: `cart.views.cart_add` проверяет остаток и пишет
   `{product_id: {"quantity": n}}` в сессию.
2. Страница корзины показывает актуальные цены и убирает товары, которых больше нет
   в продаже (`Cart.prune`).
3. `orders.views.checkout` валидирует `CheckoutForm`.
4. `orders.services.create_order_from_cart` в одной транзакции блокирует товары,
   перепроверяет остатки и цены, создаёт `Order`/`OrderItem`, списывает остатки
   и очищает корзину.
5. Номер заказа вида `FM-20261020-A7K2Q` показывается на странице подтверждения;
   заказ доступен для обработки в админке.
6. При создании заказа появляется событие истории «Заказ оформлен на сайте».
   Смена статуса в админке (кнопками действий или вручную) добавляет новое событие.
7. Покупатель открывает `/orders/track/`, вводит номер и телефон и видит таймлайн,
   историю, состав и суммы; страница подтверждения сразу даёт доступ к отслеживанию.

## Отслеживание заказа

- Вход в отслеживание — кнопка «Отследить заказ» в шапке сайта рядом с корзиной
  (а также на странице подтверждения заказа).
- Страница `/orders/track/` принимает номер заказа и телефон. Сравнение телефонов
  идёт по последним 10 цифрам, поэтому `+7 (999) 123-45-67`, `89991234567`
  и `+7 999 123 45 67` считаются одним номером.
- При неверной паре показывается одинаковое сообщение «заказ не найден» — нельзя
  перебором узнать, существует ли заказ.
- После успешной проверки заказ запоминается в сессии (до 20 последних), и страница
  `/orders/track/<номер>/` открывается без повторного ввода. Прямой переход по такой
  ссылке без проверки перенаправляет на форму.
- Таймлайн этапов: «Заказ принят» → «Заказ подтверждён» → «В доставке» → «Выполнен».
  Для отменённого заказа показывается предупреждение, а пройденные этапы остаются
  отмеченными.
- В админке у заказа есть встроенная «История статусов»; каждое изменение статуса
  фиксируется с комментарием и временем и сразу видно покупателю.

## Поиск по каталогу

Поиск ищет по названию и описанию без учёта регистра, в том числе для кириллицы.
Так как SQLite не умеет регистронезависимый `LIKE` для не-ASCII символов, у товара
есть служебное поле `search_text` — нормализованная строка, которая пересобирается
при сохранении товара. На PostgreSQL этот же запрос работает через обычный `LIKE`
по уже нормализованным данным. Для больших каталогов стоит перейти на полнотекстовый
поиск (PostgreSQL `tsvector` или Elasticsearch).

## Модели

- `catalog.Category` — название, slug, иконка-эмодзи, цвет, порядок, активность.
- `catalog.Product` — категория, название, slug, цена, старая цена, единица,
  остаток, доступность, «хит», эмодзи и необязательная ссылка на фото.
- `orders.Order` — номер, статус, контакты, способ получения, адрес и время,
  оплата, суммы, комментарий, даты.
- `orders.OrderItem` — снимок названия, единицы и цены на момент заказа.
- `orders.OrderStatusEvent` — история статусов заказа: статус, комментарий и время.

## Настройки магазина

В `config/settings.py`:

| Параметр | Назначение | Значение по умолчанию |
| --- | --- | --- |
| `SITE_NAME` | Название магазина | `ФрешМаркет` |
| `SITE_PHONE` | Телефон поддержки | `+7 (800) 555-35-35` |
| `FREE_DELIVERY_FROM` | Порог бесплатной доставки | `2000` ₽ |
| `DELIVERY_PRICE` | Стоимость доставки курьером | `299` ₽ |

Переменные окружения:

- `DJANGO_SECRET_KEY` — секретный ключ (по умолчанию небезопасный демонстрационный);
- `DJANGO_DEBUG` — `0`, чтобы выключить режим отладки;
- `DJANGO_ALLOWED_HOSTS` — список хостов через запятую.

Иллюстрации товаров по умолчанию — эмодзи на цветной подложке категории.
Чтобы показывать фотографию, заполните у товара поле «Ссылка на фото»
(`image_url`) в админке — изображение заменит эмодзи.

## Перед публикацией в интернете

- Задайте `DJANGO_SECRET_KEY`, `DJANGO_DEBUG=0` и реальный `DJANGO_ALLOWED_HOSTS`.
- Перейдите на PostgreSQL и выполните `python manage.py collectstatic`
  (раздавайте статику через веб-сервер или WhiteNoise).
- Включите HTTPS, `CSRF_TRUSTED_ORIGINS` и безопасные cookie.
- Настройте почтовый бэкенд для чеков (сейчас письма не отправляются).
- Подключите платёжный провайдер, если нужна онлайн-оплата.
- Смените или удалите демонстрационного пользователя `admin`.
